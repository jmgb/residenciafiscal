# Firmas que el repositorio declara para las RPC del contrato operativo.
#
# Es la respuesta a la cuarta pregunta del subsistema: ¿la base de datos es la
# que el repositorio dice? Las otras tres ya tienen guardián —backup fresco,
# dump contra Supabase, checkout contra git—, y esta no lo tenía. El 3 de agosto
# de 2026 se editaron en sitio dos migraciones ya aplicadas y producción se
# quedó ocho días con `private.purge_expired_deep_research_jobs` de un solo
# argumento mientras el repositorio la declaraba con tres; nada lo dijo hasta
# que un script del VPS la llamó y falló.
#
# Una línea por firma viva, tal y como la imprime
# `pg_get_function_identity_arguments`, incluidos los nombres de parámetro:
# un renombrado también rompe a quien llama por nombre.
#
# Las sobrecargas se declaran una a una y a propósito. Sobra o falta cualquiera
# de ellas, `check-database-contract.sh` lo canta: así se detecta también una
# firma antigua que sobrevivió a su sustituta.
#
# Al cambiar una firma en una migración hay que actualizar esta lista en el
# mismo cambio; `tests/test_database_contract.py` no deja que se olvide.
